Help and support

An offline encryption utility. Free, with no ads, in-app purchases or server account.

Report a problem

Get support through GitHub Issues

Issues are public and submitting one requires a GitHub account. Include only app/iOS versions, device model, steps and error text. Do not post names, phone numbers, email addresses, private keys, backup passwords or private conversations. Redact screenshots. For private requests, use the contact channel shown inside the app under Settings → About and Help → Help and Support.

How do I start?

Create an identity and public receive card in the app. In Friends, scan or import a friend’s card and compare the full fingerprint with them. Share public cards, never private keys or identity backups.

How do I encrypt in the keyboard?

Enable sharing of verified public cards in the app. Add Little Notes under iOS Settings → General → Keyboard → Keyboards. In a field allowing third-party keyboards, choose your friend, write and tap Encrypt & insert, then send separately in the host app. iOS may use its own keyboard for secure fields.

How do I decrypt?

Enable keyboard Full Access in iOS and grant a 15-minute key session in the main app. Copy complete ciphertext, switch to Read and explicitly paste. The result stays in the keyboard panel. Return to the app to renew an expired session.

Does Full Access upload my typing?

There is no messaging server or network transfer implementation. Full Access is used for local sharing and related functions. iOS also grants network capability; it is not a separate network-denial permission.

Why is history missing or a message unreadable?

Check the separate retention options and keyboard authorization, then return to the main app to import records. Check the recipient, original identity key, complete ciphertext and session expiry. Additional password combinations run in the main app. A newly created key cannot decrypt old messages.

How do I clear data?

Manage optional local learning in keyboard settings. Learning is initially off. Clear all sensitive information deletes app-managed local data and cannot be undone inside the app. Back up any keys you need first. External copies are outside this deletion.

Contact-specific schemes (0.12.9 and later)

Exchange and verify receive cards first. Under Friends, create a contact-specific scheme with 1–10 ordered layers of the supplied public algorithms. Export the scheme encrypted to the friend’s public key. The recipient compares the full scheme fingerprint, confirms import and returns an encrypted receipt. The creator can enable it after receiving that receipt. Keep the scheme on both devices: identity-key backups do not include scheme secrets.

Encryption button unavailable?

Select a recipient and enter text. Ordinary public-key encryption does not require Full Access. Contact-specific schemes require a current, explicitly authorized keyboard session from the main app. Additional password profiles must be used in the main app, or explicitly choose basic protection for that message when offered. Protection is never silently downgraded.
